# Ship and spike learnings (EDU-13 epic, EDU-18 and EDU-19, 2026-10-09)

Aggregated from the two `/ship` runs under `/spike`, then checked against the fogado repo's `fogado-e2e`, `ship` and `spike` skills (ship v3.3, about 96 real tickets). Each item says where the evidence came from and which file changes. Evidence tags: **run** = seen in the 18/19 transcripts, **fogado** = already solved there, **new** = neither.

Results: EDU-19 reached draft PR #45 with CI green in 61 min. EDU-18 was still in simplify attempt 2 after 108 min. About 30 min of that was ship idle, and 12 min was a host-wide kill.

## Already in your working tree (uncommitted, unverified here)

`git diff` shows these edits in progress, so the items below build on them rather than redo them: e2e is **required** for every product-code change (ADR 0004 amended, D-051); the `api` e2e verdict is retired and `e2e-gate.sh` emits only `skip` or `browser`; `stages.md` step 6 now halts on any non-PASS e2e, BLOCKED included, and demotes `state.sh skip-e2e` to a manual override; `verification-status.md`, `CLAUDE.md` and `docs/verification.md` were touched to match.

Consequence: with e2e mandatory, a stack that fails to start now halts the pipeline instead of being skipped, so A1 to A3 matter more than before.

## Headline

Eduvault already has the right stack primitive, `eduvault-e2e/scripts/stack-worktree.sh` (own ports from 3710/4720/4721, own database, pid state). Ship never uses it: `ship/scripts/stack.sh` runs `pnpm dev` on fixed ports 3000/4200/4201 and ends in `exec pnpm dev`. Fogado's `ship/scripts/stack.sh` wraps its `stack-worktree.sh` instead. Most of the lost time traces to that one gap.

**Revision to B9 (human merge).** `--auto-decide` now also runs the finish step: once the merge gate passes, ship runs `finish.sh --yes --via=auto-decide` itself, so an autonomous run merges and closes its issue with no human gate. This is `--finish` made implicit, not fogado's `merge.sh`: it is still the same guard (squash at the gate's head, no `--admin`, refuses red, pending or conflicting PRs). `hold-merge` stays the brake (the ticket parks as `held`). A run without `--auto-decide` is unchanged: a human merges, or types `--finish`. Reason: an autonomous run with a human merge gate is not autonomous, and under `/spike` it stalls every dependent ticket until someone merges.
