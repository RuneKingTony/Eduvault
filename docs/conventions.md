# Conventions

How code is written in this repo, and which gate rejects it when it isn't. Tenancy and module boundaries are in [architecture.md](architecture.md); the gates themselves are in [verification.md](verification.md).

**Enforced by** names the gate: an ESLint rule, `tsc`, `prettier`, `knip`, `drift`, an integration test, or `review` when nothing static can catch it. Every ESLint rule is `error`; the Nx lint target has no `--max-warnings`, so a warning would be invisible. Plugin presets that ship `warn` rules go through `asErrors` in `eslint.config.mjs`, which promotes them. The React Compiler diagnostics `react-hooks/incompatible-library` and `unsupported-syntax` are off because the repo does not use the compiler.

## Where the lint rules live

| Layer                        | File                                 | Applies to                                                                                                                                                                                              |
| ---------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base                         | `eslint.config.mjs` (default export) | Every project: typescript-eslint strict and stylistic, **type-checked** (`projectService`), module boundaries, naming, file names, the sonarjs, unicorn, regexp and import-x presets, complexity limits |
| `reactConfig`                | `eslint.config.mjs` (named export)   | `web-admin`, `web-portal`, `libs/ui`, `libs/auth-client`: React, hooks, jsx-a11y, TanStack Query                                                                                                        |
| `spaConfig`                  | `eslint.config.mjs` (named export)   | `web-admin`, `web-portal` only: no `fetch`, no `better-auth`, no server packages, env only in `src/env.ts`                                                                                              |
| `tailwindConfig(entryPoint)` | `eslint.config.mjs` (named export)   | `web-admin`, `web-portal`, `libs/ui`, `libs/auth-client`: Tailwind 4 class hygiene and no raw palette colours, each given its CSS entry point                                                           |
| API                          | `apps/api/eslint.config.mjs`         | `apps/api`: runtime imports for Nest DI, no class-level auth, no `process.env`, no client packages                                                                                                      |
| Specs and test dirs          | `eslint.config.mjs`                  | `*.spec.*`, `test/**`: `no-unsafe-*`, `unbound-method`, non-null assertions relaxed                                                                                                                     |

`files` globs in a project's config resolve against that project, so `src/**` in `apps/api/eslint.config.mjs` means `apps/api/src/**`. To add a rule, put it in the narrowest layer that covers every file it should reject, run `nx run-many -t lint`, fix or tune until it is green, and only then add its row to the tables below.

ESLint stays on 9: `eslint-plugin-react` and `eslint-plugin-jsx-a11y` do not support 10 yet, so `eslint-plugin-unicorn` is held at `^64` (v66 and later need ESLint 10). Move them together when those plugins catch up. `@types/node` is pinned to the catalog through a pnpm `overrides` entry because `eslint-plugin-regexp` pulls in `@types/node@26`, which would give pnpm a second Vite and Vitest to type-check against.

## Backend (`apps/api`)

Layout: `src/app/modules/<name>/<name>.{module,controller,service,repository}.ts` plus `kysely-<name>.repository.ts`, shared infrastructure in `src/app/common/{auth,config,db,http}`. A module imports `common`, and another module only through what its module exports (a service), never its internals. The request path is controller → service → repository; all SQL lives in the repository, so changing ORM means rewriting the `kysely-*.repository.ts` files and `common/db`.

## Frontend (`apps/web-admin`, `apps/web-portal`, `libs/ui`)

Layout: `src/pages/*-page.tsx` (one routed page per file), `src/components/` (app-specific pieces), `src/api.tsx` (the `ApiProvider` and `useApi`), `src/auth.ts`, `src/env.ts`, `src/queries.ts` (`queryOptions` factories taking `api`, shared by pages and loaders), `src/query-client.ts`, `src/router.tsx` (creates the router with `queryClient` and `api` in its context), `src/routes/` (file-based TanStack Router routes) and the committed, generated `src/routeTree.gen.ts`. Reusable presentational primitives live in `libs/ui`; the Better Auth client and auth-aware widgets (`SignInForm`, `SchoolSwitcher`, `UserMenu`) and the session-and-profile gate both apps share (`EntryGate`, `MeGate`, which reads `GET /me` through TanStack Query) live in `libs/auth-client`. Each app's `src/nav.ts` is its navigation as data, and the shell in `src/components/` shows only items whose route exists.

## Not enforceable by a gate

These need a reviewer. Do not read a green `pnpm validate` as proof they hold.

- **Tenancy filtering.** A query missing `organization_id` or the campus scope compiles, lints and passes unit tests. Only an integration case with a second school or campus catches it.
- **404 versus 403.** Out-of-scope rows answer 404; only a role lacking a permission answers 403. Nothing static tells the two apart.
- **Column casing.** Domain tables are `snake_case` and Better Auth tables camelCase. `drift` pins the generated types, and `naming-convention` deliberately ignores object and type properties, so Kysely column keys are not linted.
- **Component design.** Named exports, `libs/ui` placement, semantic tokens and whether state belongs in a query are judgement calls.
- **Naming a thing well**, and whether a comment earns its place.

If a rule from these tables keeps being broken in review, promote it: add the narrowest ESLint rule that catches it, make it green, and move its row's **Enforced by** from `review` to the rule.
