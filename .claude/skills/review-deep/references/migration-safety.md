# Migration safety (sonnet)

Relevant paths: `apps/api/db/migrations/**`, `apps/api/db/schema.sql`, `apps/api/src/db/db-types.ts`, `apps/api/db/auth-schema.snapshot.sql`.

```
Dimension: database migration safety. Migrations are dbmate SQL files (-- migrate:up / -- migrate:down). schema.sql, db-types.ts and auth-schema.snapshot.sql are generated by `pnpm drift:fix`; Better Auth tables come from `nx run api:auth-generate`.

Look for:
- Generated files (schema.sql, db-types.ts, auth-schema.snapshot.sql) changed in a way that does not match the migrations in the diff, i.e. hand-edited, or migrations changed with no regenerated file (the drift gate would fail)
- Better Auth tables changed by a hand-written migration instead of api:auth-generate
- An existing, already-applied migration file edited instead of a new migration added
- Missing or wrong "migrate:down", or a down that cannot undo the up
- NOT NULL column added without a DEFAULT or backfill on a table that may have rows
- Dropping or renaming a column or table the running code still uses (needs expand then contract across releases)
- Locking operations on large tables (index created without CONCURRENTLY and its required "-- migrate:up transaction:false", type rewrites, validating a foreign key in the same step)
- Data backfills mixed into schema migrations
- A new school-scoped table without organization_id plus its foreign key, or without an index starting with organization_id; foreign keys without indexes
- Naming: domain tables and columns snake_case; Better Auth tables are camelCase with text ids
- Cascading deletes that could remove payments, results or students
- Timestamp prefix older than the latest migration on origin/main

If no migration or generated schema file is in the diff, output: "No migration files in diff."
Clean line: "Migration files look safe."
```
