# merge-gate: read when pr has passed

The gate waits for CI and stops. A human merges. `bash $W/state.sh stage <KEY> merge-gate running`, then
in the background `bash $W/merge-gate.sh <KEY> $RUN_ID` (it prints `waiting on <checks> (<elapsed>)` as CI
moves; relay the latest when asked):

| exit | then                                                                                                                                                                                                                                                                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | CI green, PR open and mergeable, not held. It recorded `pass`. Go to cleanup                                                                                                                                                                                                                                                                                                                       |
| 1    | halt naming the failed checks; the output ends with each failed job's error lines. Red on an up-to-date branch: a branch behind main was already synced once, and a run whose logs show no test, lint or type error was already rerun once                                                                                                                                                         |
| 20   | conflicts with main: a **merge-sync** worker turn (stage keyed `merge-sync`, prompt from `prompt.sh`, verified with `verify.sh <KEY> merge-sync`, which records `merge-sync pass` itself; with `unrun_specs`, run those first, then `state.sh stage <KEY> merge-sync pass`). If its `app_conflicts` is true: `state.sh set <KEY> 'del(.stages.e2e)'` and run e2e again. Then `merge-gate.sh` again |
| 21   | halt: PR not open                                                                                                                                                                                                                                                                                                                                                                                  |
| 23   | halt: held, `hold-merge` is on the issue or the PR. Recorded `held`, so a resume reruns the gate. The PR stays open; nothing merges it to get past this                                                                                                                                                                                                                                            |
| 30   | halt: timed out waiting for checks                                                                                                                                                                                                                                                                                                                                                                 |

Never `gh pr merge`, never `--admin`, never `gh pr ready`. After exit 0 the final report says CI is green and
the PR is ready for a human to mark ready and merge.
