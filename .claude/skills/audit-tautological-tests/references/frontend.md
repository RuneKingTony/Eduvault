# Front end (apps/web-admin, apps/web-portal, libs/ui, libs/auth-client)

Tests run on Vitest with Testing Library (`render`, `screen`, `within`, `userEvent`). Each app has a `test-utils.tsx` and `test-*.ts` fixture files. `renderWithApi(ui, api, access)` wraps the page in `ApiProvider` with a fake `api` object of `vi.fn()` methods.

## What the front end gets right

Queries are user-facing (`getByRole`, `getByLabelText`, `findByText`, `within(row)`), there are no snapshots, `getByTestId` appears in two files, and many specs assert the screen after an action. Do not flag these.

## Patterns to look for

| Pattern                                                                                                                       | Why it can pass when the page is wrong                                                                                                                                                           | Grade                                                      |
| ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Fake API typed `Partial<Record<keyof Api, unknown>>`                                                                          | Response shapes and method signatures are not checked against `ApiClient<AppContract>`, so a fake can return what the real API never would                                                       | Systemic weak oracle                                       |
| Spy-only test with no rendered outcome                                                                                        | Proves the request left, not that the user saw the result (dialog closed, toast, list refreshed)                                                                                                 | Weak oracle unless the request is the contract             |
| A spy on a callback the test passed in, asserted called                                                                       | Grade by the argument: a value the component derived (the clicked row's id, the chosen role) is a legitimate output of a controlled component; a value the test passed in and got back is wiring | Tautology only when echoed                                 |
| Class assertions (`toHaveClass('text-warning-ink')`)                                                                          | Pins a Tailwind class; passes while the contrast is broken and fails on a harmless rename                                                                                                        | Change detector                                            |
| Third-party class names (`lucide-receipt`)                                                                                    | Pins a library's markup                                                                                                                                                                          | Change detector                                            |
| `container.firstChild`, `.closest()` chains, `getByTestId`                                                                    | Couples to DOM structure rather than what the user perceives                                                                                                                                     | Change detector (`closest('tr')` + `within` is acceptable) |
| Heading or description copy asserted literally                                                                                | Fails on every wording edit and catches no bug                                                                                                                                                   | Change detector unless the copy is a contract              |
| Symmetric fixtures (`waitingForMe`, `byNav` and `preview.length` all 2)                                                       | No assertion can tell which field the component reads; a swap stays green                                                                                                                        | Weak oracle: give each field a distinct value              |
| Fixture ids that are not UUIDs (`'ada'`, `'fl-1'`), or a fake that answers with a body the schema rejects                     | The real client parses every response with `route.response.parse` and `idSchema` is `z.uuid()`, so the fake accepts what production would refuse                                                 | Systemic weak oracle                                       |
| A fake that resolves the old state (`update` returns the unchanged rules)                                                     | The UI after the action is never asserted, or a toast figure is the fake's hard-wired value                                                                                                      | Weak oracle: make the fake stateful or echo the body       |
| Expected text built from the constant the component renders (`new RegExp(KIND_UI.x.declineEffect)`, `toEqual(STATUS_LABELS)`) | Catches wiring but not a wrong string; a constant restated against itself catches nothing                                                                                                        | Tautology (restated) or Weak (wiring only)                 |
| Two identical `toHaveBeenLastCalledWith` after two clicks with no `mockClear`                                                 | If the second click does nothing the last call is still the first                                                                                                                                | Weak oracle                                                |
| A permission test whose fake encodes the rule (`actingAccess(writes)` builds permissions from `READ_PERMS`)                   | Proves "no permission, no button", not the acting rule the server owns                                                                                                                           | Rename, and find the server twin                           |
| `accessOfStarter` with an unknown slug                                                                                        | Silently yields no permissions, so every "hidden from X" assertion passes                                                                                                                        | Make it throw                                              |
| Title claims a scope or rule the fake cannot enforce ("only their campuses" with a fake that returns both)                    | Proves only the branch the page owns                                                                                                                                                             | Rename, or make the fake return the narrowed list          |
| Mocked child component (`vi.mock('../child')`)                                                                                | The test no longer renders the integration it names                                                                                                                                              | Tautology risk                                             |
| Query-cache tests counting `toHaveBeenCalledTimes`                                                                            | Mirrors which keys the implementation invalidates; legitimate when it guards refetch behaviour                                                                                                   | Review per test                                            |
| `expect(getBy...).toBeInTheDocument()`                                                                                        | `getBy` already throws when absent; redundant but harmless                                                                                                                                       | Noise, lowest priority                                     |

Partial mocks of `@eduvault/ui` that only replace `notify`/`toast` are fine: the toast is a boundary.

## How to catch them

1. **Mutate the component, not the test.** Change a branch (invert a permission check, drop a filter) and run the spec. A green run marks the test vacuous. Prefer this to reading assertions.
2. **Type the fake.** Replace the `unknown` fake with a deep-partial of `Api` so a wrong method name or response shape fails `tsc` (`typecheck` is a gate).
3. **Test at the network boundary for flows that matter.** Mock Service Worker intercepts real requests, so the contract client, serialization and error handling stay under test; `vi.mock` of an API module skips them. Reuse the `libs/api-contract` handlers. Adopt it for money and permission flows first, not everywhere.
4. **Lint it.** `@vitest/eslint-plugin` recommended and `eslint-plugin-testing-library` (`flat/react`, plus `no-test-id-queries` and `prefer-query-matchers`) are on for every spec (`eslint.config.mjs`, D-356); `vitest/no-restricted-matchers` bans `toBeDefined`, `toBeTruthy` and `toBeFalsy`. The testing-library rules catch the DOM-structure patterns above (`.closest('tr')` becomes `getByRole('row', { name })`). Not enabled: `prefer-user-event` and `prefer-explicit-assert`. Every rule is `error` here (`conventions.md`), so fix hits rather than disabling.
5. **Interact like a user.** Specs use `userEvent` (`prefer-user-event` and `prefer-user-event-setup` are errors, D-377): `fireEvent.change` skipped focus, typing and disabled-state behaviour, so a test could pass against a control a user could not operate. Where a test needs the contract skipped for one request, use `renderWithRefusal`.
6. **Assert the outcome after the request.** For each spy-only test, add the visible result, or state in the title that the request is the contract.
7. **Hold fakes to the contract.** `checked(...)` (`test-api.ts` in each app, `contractChecked` in `libs/api-contract`) validates every fake call's request and answer against the route schemas, so fixtures need real UUIDs and real shapes. Every spec in both apps is held to it; a spec that mounts `ApiProvider` with a bare fake bypasses it, so grep for `ApiProvider api=` without `checked(`. Use real UUID constants for shared ids, and make fake write methods echo the request.
8. **Let e2e own flows.** Anything permission- or tenancy-sensitive that is only covered by fake-client component tests needs an `eduvault-e2e` step (`docs/verification.md`: sign-in and school switching are only component-tested in the default loop).

## Twins on the front end

A front-end rule's twin is, in order: an `eduvault-e2e` step (grep `.claude/skills/eduvault-e2e/references/flows.md` for the page or action), the API integration spec that owns the same rule (cite it), or a `libs/api-contract` spec. Say which kind stands in, and say when a money or permission flow has none of the first kind. In the first audit the student purchase sheet, Approvals, Approval rules, Record payment, the void request and the portal Purchases page had no browser step at all.

## Sources with no spec

Also list untested sources that decide what refreshes or who may act: query invalidators (`invalidatePayments`, `invalidateApprovals` and `invalidateFees` had none), gates, and test helpers exported from a production barrel.

## Measurements from the first audit

1,775 front-end tests: 173 spy-only, 97 single presence check, 24 assert CSS classes, 6 reach into DOM structure, 0 snapshots, 0 `userEvent`. Spy-only counts are mostly legitimate request-contract tests; the work is to check that the fake is typed and the visible outcome is asserted.
